# Hookah Party

Сайт приглашений на кальянные сборы в Бишкеке. Интерфейс на русском и английском.

- Регистрация по телефону с SMS-кодом, профиль с аватаром
- Главная: три раздела (Заведения, Кальян, События), приветствие и карта кальянных Бишкека
- Своя карта на SVG: подложка и заведения из OpenStreetMap (`map-data.js`), часы работы, «открыто сейчас», ссылки в Google Карты и 2ГИС
- Сборы: заведение, ссылки на Яндекс Карты и 2ГИС, приглашения по номеру, голосование за табаки и чашу
- Складчина: число кальянов, цена, сколько с каждого, кто уже скинулся
- Обсуждение внутри сбора, напоминание за час и выгрузка в календарь (.ics)
- Повтор сбора с теми же людьми, редактирование
- Каталог: табаки с отзывами и рейтингом, фильтры по крепости и вкусу, миксы с пропорциями, чаши, аксессуары
- Люди: друзья, страницы пользователей, история сборов, любимое заведение
- Безопасность: журнал входов, уведомление о входе с нового устройства, смена пароля и «Забыли пароль?» (вход по SMS), удаление аккаунта в настройках
- Оформление: светлая и тёмная тема, четыре цвета акцента

## Два режима работы

- **Демо** (GitHub Pages, открытие файла с диска): всё хранится в браузере, SMS-код показывается на экране. Ничего устанавливать не нужно.
- **С сервером**: настоящая база, вход по SMS, проверка прав, лимиты и журнал безопасности на сервере. Сайт сам понимает, что рядом есть сервер (`/api/health`), и переключается.

Демо включается, только если сервера на этом адресе нет и не было (на `/api/health` — 404, как на GitHub Pages и в приложении без сервера). Если сервер есть, но ответил не так — лимит запросов (429), перезапуск (5xx), данные не пришли — или пропала сеть, вместо страниц честный экран «Сервер ненадолго недоступен» или «Нет соединения», меню его не обходит, а раз в 20 секунд страница тихо пробует снова и открывается сама. Демо-данные и демо-вход на сайте с сервером не показываются; одно исключение — самое первое открытие сайта в этом браузере, когда `/api/health` не ответил вовсе (нет сети и после повторной попытки): тогда сайт ещё не знает, что сервер здесь есть, и открывает демо, как на GitHub Pages без сети. Демо-данные, оставшиеся в браузере от прежних версий, стираются при первом ответе сервера. `GET /api/health` в общий лимит запросов с адреса не входит. Браузер помнит, что на этом адресе был сервер (`hp.mode` в хранилище сайта): если при разработке на том же адресе (например, `localhost:3000`) запустить сайт без сервера, очистите данные сайта в браузере.

## Запуск с сервером

Нужен Node.js 24.7 или новее. Сторонних библиотек сервер не использует: база (SQLite), хэширование паролей (Argon2id) и шифрование встроены в Node.

```
cp .env.example .env      # при желании заполните
npm start                 # http://localhost:3000
```

При первом запуске в пустую базу добавляются тестовые данные. Тестовый вход: `+996 700 000 001`, пароль `hookah`. В режиме разработки (`SMS_PROVIDER=dev`) код из SMS не отправляется, а показывается на экране и в журнале сервера.

### Администратор

Администратор — только владелец. Нужны оба условия сразу:

1. номер владельца записан в `.env` на сервере: `ADMIN_PHONES=+996XXXXXXXXX`;
2. роль выдана из консоли сервера (через сайт её получить нельзя):

```
node server/admin.js grant +996XXXXXXXXX        # выдать (сначала зарегистрируйтесь на сайте с этим номером)
node server/admin.js revoke +996XXXXXXXXX       # забрать
node server/admin.js list                       # список администраторов и подключено ли приложение для кодов
node server/admin.js totp-reset +996XXXXXXXXX   # телефон потерян или заменён: отключить приложение для кодов, завершить сессии
node server/admin.js delete +996XXXXXXXXX       # что удалится вместе с аккаунтом (ничего не удаляет, код выхода 2)
node server/admin.js delete +996XXXXXXXXX --yes # удалить аккаунт по просьбе человека, который не может войти (см. «Удаление аккаунта»)
```

Номер не из `ADMIN_PHONES` права не получит, даже если роль записать прямо в базу. Вход в панель — в профиле владельца («Администрирование»), в меню его нет; у остальных нет ни кнопки, ни адреса: сервер отвечает «не найдено». В демо-режиме (GitHub Pages) панели нет совсем.

Панель открывается на 15 минут **паролем и шестизначным кодом из приложения** (2FA, стандарт TOTP: Google Authenticator, «Пароли» на iPhone, 1Password). Все действия попадают в журнал.

- **Первый вход.** Пароль открывает только экран подключения: QR-код, ключ для ручного ввода и поле для кода. После верного кода приложение подключено. Сделайте это сразу после запуска сервера: пока приложение не подключено, экран подключения открывается одним паролем, и приложение привяжет тот, кто успеет первым.
- **Ключ для ручного ввода** сохраните в менеджере паролей. Резервных кодов нет: без телефона и без ключа доступ вернёт только `totp-reset`.
- **Ошибки.** Один и тот же код дважды не принимается. Неверные пароли и коды считаются вместе: 5 ошибок — блокировка на 5 минут, не больше 10 в час. Время на телефоне должно устанавливаться автоматически.
- **Секрет 2FA** хранится в базе только зашифрованным ключом `DATA_KEY`.

Код панели хранится в репозитории только зашифрованным (`server/private/admin-panel.enc`, AES-256-GCM). Ключ `ADMIN_CODE_KEY` есть только в `.env` у владельца и на сервере; сервер расшифровывает панель в памяти и отдаёт её лишь администратору. Исходник `server/private/admin-panel.js` в git не попадает.

```
node server/admin.js key      # создать ключ в .env (один раз; .env сохранить в надёжном месте)
node server/admin.js pack     # зашифровать панель после правок
node server/admin.js unpack   # восстановить исходник из зашифрованного файла
node server/admin.js rekey    # сменить ADMIN_CODE_KEY: панель перешифровывается, строка в .env заменяется на месте
```

После `rekey` закоммитьте новый `admin-panel.enc`, замените `ADMIN_CODE_KEY` на сервере, перезапустите сервис и сохраните новый `.env` в менеджере паролей. Все команды `admin.js` принимают `--env <файл>` — другой файл настроек. Ключи на экран не выводятся никогда.

### Правила сборов

Один активный сбор на организатора: новый можно создать, когда текущий пройдёт, или отменив его. Не больше 12 созданий и 12 отмен в сутки. Отменить сбор может только организатор; отменённый сбор удаляется из базы целиком.

### Для работы в интернете

- `NODE_ENV=production` — cookie только по HTTPS, код из SMS не показывается;
- `SEED=0` — без демо-пользователей с паролем `hookah` в пустой базе (при `NODE_ENV=production` они не добавляются в любом случае);
- `HOST` — на каком адресе слушать (по умолчанию в production `127.0.0.1`, то есть только для nginx);
- `DATA_KEY` — ключ шифрования номеров и секретов 2FA: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`. Сменить его потом можно только командой `server/rotate-key.js` (ниже);
- `BACKUP_KEY` — ключ резервных копий: `node server/backup.js key`. Там же `BACKUP_DIR` и `BACKUP_KEEP` (сколько копий хранить, по умолчанию 14);
- `ADMIN_PHONES` и `ADMIN_CODE_KEY` — см. «Администратор»;
- `SMS_PROVIDER=nikita` или `twilio` и доступы к нему (формат запроса Nikita сверить с их актуальной документацией);
- `ALLOWED_PHONE_PREFIXES` — коды стран, с номерами которых можно зарегистрироваться и войти по SMS (через запятую, по умолчанию `996`);
- `SMS_PER_HOUR` и `SMS_PER_DAY` — бюджет SMS на весь сервер (по умолчанию 60 и 300), см. «Вход, коды из SMS и лимиты»;
- `UV_THREADPOOL_SIZE` — потоки пула libuv (по умолчанию 4), половина из них — на проверку паролей. Задаётся в окружении процесса (в systemd — `Environment=`), а не в `.env`: пул создаётся раньше, чем читается `.env`;
- `TRUST_PROXY=1`, если сервер стоит за nginx или Cloudflare: иначе все посетители будут с адреса прокси, и лимиты, fail2ban и сигналы безопасности сработают неправильно.

Копию `.env` (`DATA_KEY`, `BACKUP_KEY`, `ADMIN_CODE_KEY`) храните ещё и в менеджере паролей: без ключей данные и копии не расшифровать.

Пошаговый запуск для владельца — [deploy/SERVER-SETUP.md](deploy/SERVER-SETUP.md): VPS с Ubuntu 24.04, вход по SSH-ключу, межсетевой экран ufw, nginx и Let's Encrypt, systemd, fail2ban, журналы не дольше 90 дней, копии вне сервера, что делать при происшествиях. Готовые файлы настроек — в папке `deploy/`.

### Приглашение ссылкой

На странице сбора есть кнопки Telegram, WhatsApp и «Ссылка». С сервером ссылка содержит случайный ключ сбора: друг видит название, место, адрес, время и имя организатора (без входа), входит по номеру и отвечает «Иду» — организатор получает уведомление. В демо-режиме (GitHub Pages) данные сбора лежат прямо в ссылке, а ответ друг отправляет организатору сообщением.

- Ссылку отправляют организатор и гости, которые идут. Работает, пока сбор не прошёл (как и ответы на приглашения).
- **Сбросить ссылку** (окно «Позвать на сбор», только организатор, `POST /api/events/:id/link/reset`): если ссылку переслали посторонним, старая сразу перестаёт работать; кто уже ответил, остаётся в сборе.
- **Убрать человека из сбора** (карандаш в списке участников → «Убрать», с подтверждением; `DELETE /api/events/:id/invites` с `{ userId }` или `{ phone }`): его ответ, голоса и отметка об оплате удаляются, сбор и обсуждение он больше не видит, ему приходит уведомление. По ссылке он не вернётся (таблица `event_bans`), пока организатор сам не позовёт его снова; гости вернуть его не могут.
- В сборе не больше 60 приглашённых, каким путём ни зови (по аккаунту, по номеру, по ссылке).

### Кто что видит

- **Гость без входа** (`/api/bootstrap` без сессии): «История» и каталог. Из людей — только те, кто «на виду»: организаторы вечеров с рассказом, авторы комментариев к рассказам, отзывов и миксов, и у них только имя и фото. Ни справочника, ни списков друзей, ни дат регистрации, ни цифр номеров.
- **Вошедший:** справочник людей (имя, фото, любимое заведение и табаки, последние три цифры номера) и только свой список друзей. Свои сборы — целиком.
- **Чужой вечер из «Истории»:** название, заведение, дата, организатор, рассказ, комментарии и итоги вечера числами (`summary`: сколько было гостей, сколько раз выбирали каждый табак и чашу), кальяны и цена. Без адреса, описания, ссылки, списка гостей, их ответов, голосов и оплат. «Огонь» — числом.
- **Полный номер** пользователя видят: он сам; взаимные друзья (каждый добавил другого — кнопка «В друзья» меняет только свою сторону, уведомление о дружбе приходит один раз); организатор сбора, на который он идёт; гости, которые идут на его сбор. Остальным — последние три цифры. Ожидающие ответа и отказавшиеся номеров не получают.
- **Приглашение по номеру** остаётся приглашением по номеру, даже если номер уже зарегистрирован: владелец видит его как своё и получает уведомление, а организатор узнаёт, чей это номер, только когда тот ответит. Целиком номер видят организатор и тот, кто позвал (`invites.invited_by`).
- **Фото профиля** в `/api/bootstrap` — только версия (`avatar`), картинка — `GET /api/avatar/<id>?v=<версия>` тем, кто видит имя (вошедшим — любого, гостям — только тех, кто «на виду»): правильный тип, `nosniff`, `ETag`, кеш `private`. Сервер принимает JPG, PNG или WebP до 100 КБ и проверяет, что это действительно картинка; страница пережимает фото в JPEG 256×256 и укладывается в лимит. Офлайн-скрипт (`sw.js`) адреса `/api/` не кеширует.

### Вход, коды из SMS и лимиты

- **Номера:** регистрация, вход по SMS и приглашение по номеру — только для номеров с кодом +996 (`ALLOWED_PHONE_PREFIXES`). На номера других стран, в том числе платные, SMS не уходят. Список кодов страница получает в `/api/bootstrap` (`phoneCodes`), в демо — те же +996.
- **Код из SMS** — 6 цифр, действует 5 минут, 5 попыток. Код привязан к запросу: `POST /api/auth/sms` отдаёт ключ запроса (`challenge`), и без него код не проверяется — чужие попытки не сжигают чужой код. Новый запрос — новый код и новый ключ.
- **Номер не узнать:** на запрос кода сервер отвечает одинаково и за одно время, есть номер в базе или нет — SMS уходит уже после ответа. Код приходит, только если им можно воспользоваться: для входа — на зарегистрированный номер, для регистрации — на новый. На уже зарегистрированный номер при регистрации приходит SMS «на этот номер уже есть аккаунт». Неверный код в обоих случаях — просто «код не подходит».
- **Чужие не закроют вход молча:** на номер считаются только неверные пароли (17 в час; удачный вход и запросы кода их не тратят). Они и блокировка после 5 неверных подряд закрывают только вход паролем, вход по коду из SMS остаётся. Закрыть и его посторонний может только шумно: сам запрашивая коды на этот номер (новый запрос заменяет прежний код, на номер — 3 кода за 10 минут). Каждый такой код приходит владельцу SMS и тратит бюджет SMS сервера; от этого пока защищают только лимиты с адреса (см. SECURITY.md, «Что ещё предстоит»).
- **Лимиты с адреса** считаются по IPv4 или по сети /64 у IPv6 (перебор адресов внутри своей сети их не обходит), в журнал пишется полный адрес: 17 попыток входа, кодов и регистраций в час; кодов из SMS — 10 в час и 30 в сутки; 3 новых аккаунта в сутки — проверяется и при запросе кода, и при самой регистрации.
- **Бюджет SMS сервера** — `SMS_PER_HOUR` и `SMS_PER_DAY` на все номера вместе, по журналу (переживает перезапуск). С 80% суточного администратору приходит сигнал, на 100% коды не уходят (ответ 503 с `Retry-After`), пока окно не освободится; вход паролем работает.
- **Проверка пароля (Argon2id)** занимает поток из общего пула libuv: одновременно считается не больше половины пула (по умолчанию 2 из 4), ещё 32 ждут, остальным — 503 «сервер занят» с `Retry-After`. Шквал попыток входа не останавливает сайт.

### Смена пароля и «Забыли пароль?»

Профиль → Настройки → «Безопасность» → «Сменить пароль»: текущий пароль, новый (с индикатором надёжности, те же требования, что при регистрации) и повтор. Ошибки показываются у своих полей.

- **На сервере** (`POST /api/me/password`, нужен вход и CSRF-токен): новый пароль не может совпадать с прежним. После смены завершаются все остальные сессии и забываются другие устройства (вход с них снова пришлёт уведомление), у этой сессии меняется токен в cookie. Пользователю приходит уведомление «Пароль изменён» с устройством и адресом без последних цифр, в журнал — `password_changed`.
- **Защита:** 5 неверных текущих паролей подряд — смена блокируется на 5 минут; каждый неверный входит в общий с входом часовой счётчик неверных паролей номера (17). Неверные попытки (`password_change_fail`, `password_change_locked`) видит fail2ban.
- **«Забыли пароль?»** на странице входа — вход по коду из SMS, после него сразу открывается окно смены пароля. Первые 15 минут после входа по SMS текущий пароль не нужен: сервер помнит время входа в самой сессии (`sessions.via_sms_at`) и сообщает об этом странице (`passwordResetAllowed` в `/api/bootstrap`). Вход паролем этого права не даёт, после смены оно сбрасывается.
- **Если пришло уведомление о незнакомом входе** — смените пароль: чужая сессия завершится. Если пароль сменили не вы — войдите по SMS и смените его снова.
- **В демо-режиме** — то же окно и те же правила на данных браузера (PBKDF2, 5 попыток, блокировка на 5 минут).

### Удаление аккаунта и сроки хранения

Пользователь удаляет аккаунт сам: Профиль → Настройки → «Удаление аккаунта». Нужно ввести пароль и отметить «Понимаю, что восстановить аккаунт нельзя».

- **На сервере** (`POST /api/me/delete`) одной транзакцией стираются профиль и номер, сессии и устройства, его сборы со всем содержимым, ответы, голоса, сообщения и реакции, отзывы, миксы и лайки, друзья, уведомления, приглашения и коды SMS на его номер. Любая новая таблица со столбцом `user_id`, `author_id`, `actor_id`, `host_id`, `friend_id`, `owner_id` или `phone_idx` очищается автоматически.
- **Гости** его предстоящих сборов получают уведомление «Сбор отменён: организатор удалил аккаунт».
- **Журнал безопасности** не удаляется, а обезличивается.
- **Защита:** 5 неверных паролей подряд — удаление блокируется на 5 минут; неверные попытки входят в общий с входом часовой счётчик неверных паролей номера.
- **Без следов:** база затирает удалённое нулями (`PRAGMA secure_delete`), а после удаления аккаунта и при ежечасной чистке переносит WAL в файл базы и обнуляет его. Резервная копия пересобирается без свободных страниц (`VACUUM`), так что в копиях, сделанных после удаления, его данных нет. Базу, созданную до этого правила, сервер один раз пересобирает при запуске.
- **В демо-режиме** — та же проверка пароля, и те же данные стираются из браузера.
- **Если войти не получается** (нет ни пароля, ни доступа к номеру), человек пишет владельцу сайта, и тот удаляет аккаунт из консоли сервера — сначала убедившись, что просит владелец номера: `node server/admin.js delete +996XXXXXXXXX` покажет, что удалится, `--yes` удалит. Удаление то же самое (общий код в `lib/retention.js`): гостям — уведомления об отмене, журнал обезличивается, в журнал — `account_deleted` с последними цифрами номера и пометкой `console`.

Сроки хранения (`server/lib/retention.js`, при запуске сервера и раз в час): журнал безопасности — 90 дней, IP-адрес регистрации (`users.created_ip`) — 90 дней, журнал созданий и отмен сборов — 2 дня, истёкшие сессии и коды — сразу, устройство в списке — год после последнего входа с него. В сессии вместо User-Agent хранится подпись устройства без версий («Chrome · macOS», `lib/ua.js`); сырой User-Agent из старых сессий чистка заменяет такой подписью. Журнал в браузере тоже хранится не дольше 90 дней. Каждая чистка заодно переносит WAL в файл базы и обнуляет его: удалённое за час (отменённые сборы, сообщения) не остаётся и там. Резервных копий хранится 14, поэтому данные удалённого аккаунта исчезают из копий за 14 дней (в копиях, сделанных после удаления, их уже нет). Если меняете `BACKUP_KEEP` или расписание копий, поправьте текст политики конфиденциальности.

### Сигналы безопасности

- **Вход с нового устройства.** Сервер запоминает устройство: браузер, система и тип, без версий. Вход с незнакомого устройства присылает уведомление «Вход с нового устройства». Список устройств — в Профиль → Настройки → «Безопасность». «Выйти на всех устройствах» завершает все сессии и забывает остальные устройства.
- **Сигналы владельцу.** Администратор (роль + номер в `ADMIN_PHONES`) получает уведомление «Безопасность», если:
  - вход в аккаунт заблокирован после 5 неверных паролей;
  - скрытую панель ищут 3 раза за 10 минут;
  - панель заблокирована после 5 неверных паролей или кодов;
  - пришло 5 отчётов CSP за 10 минут;
  - панель открыта с нового адреса;
  - израсходовано 80% суточного бюджета SMS и отправка SMS остановлена (100%).

  Каждый вид сигнала приходит не чаще раза в 30 минут. Номера и IP в сигналах скрыты. Уведомления о безопасности выключить нельзя.
- **Заблокированный код.** Если браузер заблокировал код по политике безопасности (CSP или Trusted Types), страница записывает это в журнал браузера. С сервером она ещё и шлёт короткий очищенный отчёт `POST /api/csp-report`: без входа, не больше 5 за загрузку страницы и 20 в час с адреса, в журнал — не больше 300 в час со всех адресов. В журнале это тип `csp_violation`.

### Резервные копии (зашифрованные)

```
node server/backup.js key                              # один раз: создать BACKUP_KEY в .env (на экран не выводится)
npm run backup                                         # копия в server/data/backups, хранятся последние BACKUP_KEEP (14)
node server/backup.js /путь/к/папке                    # своя папка
npm run restore -- <копия.db.enc> <новый-файл.db>      # расшифровать в новый файл, проверить, показать число строк по таблицам
```

Копия делается без остановки сервера, проверяется (`integrity_check`) и шифруется AES-256-GCM ключом `BACKUP_KEY` в файл `hookah-<время>.db.enc`. Открытая копия на диске не остаётся, старые незашифрованные копии `hookah-*.db` удаляются. Без `BACKUP_KEY` копия не делается. Восстановление пишет только в новый файл; неверный ключ или изменённый файл дают ошибку, а не испорченную базу. Ночная копия на сервере в 05:30 — `deploy/hookah-backup.service` и `.timer`, копии вне сервера (по желанию) — `deploy/hookah-offsite.*`.

### Смена ключа данных DATA_KEY

```
sudo systemctl stop hookah-party
sudo -u hookah node server/rotate-key.js       # локально: npm run rotate-key
sudo systemctl start hookah-party
node server/rotate-key.js --check              # только проверить, что вся база читается текущим ключом
```

Перед сменой делается зашифрованная копия. Затем одной транзакцией перешифровываются все колонки `*_enc` (номера, секреты 2FA), пересчитываются индексы номеров, удаляются коды из SMS, и всё проверяется новым ключом. Строка `DATA_KEY` в `.env` заменяется на месте, ключ на экран не выводится. Прежний ключ сохраняется в `server/data/old-data-key-<время>.env`: он нужен только для копий, сделанных до смены. Когда они устареют (14 дней), удалите файл. Просто вписать в `.env` новый `DATA_KEY` нельзя — номера перестанут читаться.

### Ошибки на страницах

Если у пользователя на странице случается ошибка, сайт сообщает о ней серверу (`POST /api/client-errors`, не больше 5 за визит и 20 в час с адреса) — она попадает в журнал сервера с пометкой «Ошибка на странице».

## Приложение для iPhone

**Без App Store, прямо сейчас.** Откройте сайт в Safari → «Поделиться» → «На экран „Домой“». Сайт откроется на весь экран со своей иконкой. Этой ссылкой можно делиться: https://marlendiusheew-sudo.github.io/hookah-party/

**Нативное приложение** — папка `ios/` (SwiftUI + WKWebView). Сайт встроен в приложение вместе со шрифтами и работает без интернета в демо-режиме; если в `ios/HookahParty/Info.plist` указать `HPServerURL` (адрес сервера на https), приложение работает с настоящими данными. Ссылки на карты открываются в приложениях, календарь — через «Поделиться», обновление — потянуть экран вниз. Если сайт не загрузился (нет сети), появляется экран «Нет соединения»: потянуть вниз или кнопка «Повторить» открывают сайт заново.

```
ios/build.sh sim              # собрать и открыть в симуляторе (подпись не нужна)
ios/build.sh ipa ВАШ_TEAM_ID  # подписанный .ipa для TestFlight / App Store
```

- **На свой iPhone:** откройте `ios/HookahParty.xcodeproj` в Xcode → Settings → Accounts → войдите с Apple ID → у цели HookahParty выберите Team → подключите iPhone → Run. С бесплатным Apple ID приложение работает 7 дней, потом нужно поставить заново.
- **Раздать другим:** нужна программа Apple Developer (99 $ в год). Затем `ios/build.sh ipa TEAM_ID` и загрузка в App Store Connect → TestFlight: друзья ставят приложение по ссылке-приглашению.
- **Неподписанный .ipa** собирается так же, как для iPhone, но с `CODE_SIGNING_ALLOWED=NO`; поставить его можно только после подписи своим Apple ID (например, через Sideloadly).

## Файлы

- `index.html` — разметка, шапка и подвал
- `styles.css` — стили, светлая и тёмная тема
- `app.js` — данные, вход, сборы, каталог, карта, переводы `L('рус', 'eng')`
- `server/` — сервер:
  - `index.js` — HTTP, заголовки, сессии, CSRF;
  - `lib/api.js` — все действия и проверка прав;
  - `lib/db.js` — схема SQLite;
  - `lib/secure.js` — Argon2id, шифрование AES-256-GCM, токены;
  - `lib/guard.js` — лимиты и журнал;
  - `lib/sms.js` — провайдеры SMS;
  - `lib/retention.js` — сроки хранения и удаление аккаунта;
  - `lib/totp.js` и `lib/qr.js` — коды 2FA и QR-код, без библиотек;
  - `lib/alerts.js` — сигналы владельцу;
  - `lib/ua.js` — устройство по User-Agent;
  - `lib/envfile.js` — чтение и правка `.env`;
  - консольные команды `admin.js`, `backup.js`, `rotate-key.js`.
- `deploy/` — настройки сервера (nginx, systemd, ufw, fail2ban, SSH, журналы, автообновления) и пошаговый запуск `SERVER-SETUP.md`
- `scripts/check-secrets.js`, `.githooks/pre-commit` — поиск секретов перед коммитом и в CI
- `ios/` — приложение для iPhone (проект Xcode, иконка, экран запуска, `build.sh`)
- `manifest.webmanifest`, `icon-*.png` — установка сайта на экран «Домой»
- `sw.js` — офлайн-режим: как страницу сайта хранит только саму страницу (корень или `index.html`) и только HTML, файлы с `?v=` и шрифты — из кеша
- `fonts/` — шрифты Unbounded, Golos Text и JetBrains Mono (WOFF2, наборы latin, cyrillic и cyrillic-ext — киргизские буквы; лицензия SIL OFL — `fonts/OFL.txt`). Сайт берёт их у себя, а не у Google Fonts: страницы не обращаются к сторонним серверам. Новый файл шрифта — новое имя с версией (кешируется надолго)
- `art.js` — иллюстрации вкусов табака (SVG, рисуются кодом; набор предметов — поле `art` у табака)
- `map-data.js` — подложка карты и заведения (© участники OpenStreetMap, ODbL)

## Тесты

```
npm install
npm test                  # всё ниже, несколько секунд
npm run test:security     # только защита от XSS и набор атак
```

Что проверяется:

- **сайт в демо-режиме** (`tests/smoke.test.js`): около 170 проверок в jsdom, в том числе смена пароля и «Забыли пароль?», что фильтр разметки пропускает всю разметку сайта без потерь и что сайт с сервером не показывает демо-данные ни при лимите запросов, ни при сбое сервера, ни без сети;
- **защита от XSS в браузере** (`tests/xss.test.js`): зловредные строки во всех пользовательских полях, открываются все страницы — нет ни обработчиков `on*`, ни `<script>`/`<iframe>`, ни ссылок `javascript:`, и ни одна строка не доходит до фильтра разметкой; сам фильтр — на формах, которые обходят фильтры на регулярных выражениях (атрибут после «/» или вплотную за кавычкой, «>» в кавычках, SVG и MathML, noscript, srcdoc, ссылки с табуляцией и HTML-сущностями);
- **сервер** (`tests/server.test.js`): вход, права, CSRF, лимиты, регистрация, приглашение по ссылке, 2FA администратора, смена пароля и «Забыли пароль?», удаление аккаунта (и из консоли — `admin.js delete` на временной базе с одноразовым ключом), сроки хранения, сигналы безопасности, заголовки; кто что видит: полные номера (взаимные друзья, «иду» в сборе, приглашение по номеру), справочник для гостя и вошедшего, чужие вечера из «Истории», смена ссылки и «Убрать из сбора», фото по отдельному адресу; проверка паролей под нагрузкой (503 «занято»), коды из 6 цифр, тег AES-GCM ровно 16 байт, удалённое не остаётся ни в файле базы и WAL, ни в копиях;
- **набор атак на сервер в памяти** (`tests/attack.test.js`): инъекции во все текстовые поля, матрица прав, CSRF и Origin, кривой HTTP, фаззинг всех маршрутов, перебор и лимиты; лимиты по сети /64 у IPv6, только номера +996, бюджет SMS, чужие запросы не закрывают владельцу вход, номера не перечислить ни по ответу, ни по времени.

Атакуется только свой сервер в памяти, без внешних адресов. `attack.test.js` запускается отдельным процессом, потому что счётчики лимитов живут в памяти процесса.

Сквозной тест в настоящем браузере — организатор отправляет ссылку, друг входит и отвечает; «Забыли пароль?» с входом по SMS и новым паролем; «История» без входа, фото по отдельному адресу и «Убрать из сбора»; офлайн-режим (и что переход на картинку сайта не подменяет сохранённую страницу); шрифты только со своего сайта; фильтр разметки под Trusted Types; сервер под лимитом — экран ожидания вместо демо:

```
npx playwright install chromium   # один раз
npm run test:e2e
```

Поиск секретов: закрытые ключи, токены (AWS, GitHub, GitLab, Slack, Stripe, Google, Twilio), значения `DATA_KEY`, `ADMIN_CODE_KEY`, `BACKUP_KEY` и других секретов в любом файле, кроме `.env.example`, и файлы, которым не место в git (`.env`, `*.pem`, `*.key`, `server/data/`, исходник панели).

```
npm run secrets           # все файлы под контролем git (так проверяет CI)
npm run secrets:history   # вся история всех веток
npm run hooks             # один раз в каждой копии репозитория: проверка перед каждым коммитом (git config core.hooksPath .githooks)
```

Найденное значение не печатается целиком. Ложное срабатывание — комментарий `check-secrets: allow` в той же строке. Ключ, который уже попал в git, считайте раскрытым и замените: удаление файла не убирает его из истории.

На GitHub при каждой отправке автоматически работают тесты (включая браузерный), поиск секретов, CodeQL и `npm audit`; OpenSSF Scorecard — после отправки в main и раз в неделю. Подробности — в [SECURITY.md](SECURITY.md).

Версию файлов `?v=N` в `index.html` повышать вместе с `VERSION` в `sw.js` (офлайн-кеш) — `npm test` это проверяет.
