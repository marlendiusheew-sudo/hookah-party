# Hookah Party

Сайт приглашений на кальянные сборы в Бишкеке. Интерфейс на русском и английском.

- Регистрация по телефону с SMS-кодом, профиль с аватаром
- Главная: три раздела (Заведения, Кальян, События), приветствие и карта кальянных Бишкека
- Своя карта на SVG: подложка и заведения из OpenStreetMap (`map-data.js`), часы работы, «открыто сейчас», ссылки в Google Карты и 2ГИС
- Сборы: заведение, ссылки на Яндекс Карты и 2ГИС, приглашения по номеру, голосование за табаки и чашу
- Складчина: число кальянов, цена, сколько с каждого, кто уже скинулся
- Обсуждение внутри сбора, напоминание за час и выгрузка в календарь (.ics)
- Повтор сбора с теми же людьми, редактирование
- Каталог: табаки с отзывами и рейтингом, фильтры по крепости и вкусу, миксы с пропорциями, чаши, аксессуары
- Люди: друзья, страницы пользователей, история сборов, любимое заведение
- Оформление: светлая и тёмная тема, четыре цвета акцента

## Два режима работы

- **Демо** (GitHub Pages, открытие файла с диска): всё хранится в браузере, SMS-код показывается на экране. Ничего устанавливать не нужно.
- **С сервером**: настоящая база, вход по SMS, проверка прав, лимиты и журнал безопасности на сервере. Сайт сам понимает, что рядом есть сервер (`/api/health`), и переключается.

## Запуск с сервером

Нужен Node.js 24.7 или новее. Сторонних библиотек сервер не использует: база (SQLite) и хэширование паролей (Argon2id) встроены в Node.

```
cp .env.example .env      # при желании заполните
npm start                 # http://localhost:3000
```

При первом запуске в пустую базу добавляются тестовые данные. Тестовый вход: `+996 700 000 001`, пароль `hookah`. В режиме разработки (`SMS_PROVIDER=dev`) код из SMS не отправляется, а показывается на экране и в журнале сервера.

### Администратор

Администратор — только владелец. Нужны оба условия сразу:

1. номер владельца записан в `.env` на сервере: `ADMIN_PHONES=+996XXXXXXXXX`;
2. роль выдана из консоли сервера (через сайт её получить нельзя):

```
node server/admin.js grant +996XXXXXXXXX    # выдать (сначала зарегистрируйтесь на сайте с этим номером)
node server/admin.js revoke +996XXXXXXXXX   # забрать
node server/admin.js list                   # список администраторов
```

Номер не из `ADMIN_PHONES` права не получит, даже если роль записать прямо в базу. Вход в панель — в профиле владельца («Администрирование»), в меню его нет; у остальных нет ни кнопки, ни адреса: сервер отвечает «не найдено». Панель открывается после повторного ввода пароля на 15 минут, все действия попадают в журнал. В демо-режиме (GitHub Pages) панели нет совсем.

Код панели хранится в репозитории только зашифрованным (`server/private/admin-panel.enc`, AES-256-GCM). Ключ `ADMIN_CODE_KEY` есть только в `.env` у владельца и на сервере; сервер расшифровывает панель в памяти и отдаёт её лишь администратору. Исходник `server/private/admin-panel.js` в git не попадает.

```
node server/admin.js key      # создать ключ в .env (один раз; .env сохранить в надёжном месте)
node server/admin.js pack     # зашифровать панель после правок
node server/admin.js unpack   # восстановить исходник из зашифрованного файла
```

### Правила сборов

Один активный сбор на организатора: новый можно создать, когда текущий пройдёт, или отменив его. Не больше 12 созданий и 12 отмен в сутки. Отменить сбор может только организатор; отменённый сбор удаляется из базы целиком.

Для работы в интернете:

- `NODE_ENV=production` — cookie только по HTTPS, код из SMS не показывается;
- `DATA_KEY` — ключ шифрования номеров: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`;
- `SMS_PROVIDER=nikita` или `twilio` и доступы к нему (формат запроса Nikita сверить с их актуальной документацией);
- `TRUST_PROXY=1`, если сервер стоит за nginx или Cloudflare;
- примеры настроек — в папке `deploy/` (systemd и nginx с HTTPS и ограничением частоты).

### Приглашение ссылкой

На странице сбора есть кнопки Telegram, WhatsApp и «Ссылка». С сервером ссылка содержит случайный ключ сбора: друг видит название, место и время, входит по номеру и отвечает «Иду» — организатор получает уведомление. В демо-режиме (GitHub Pages) данные сбора лежат прямо в ссылке, а ответ друг отправляет организатору сообщением.

### Резервные копии

```
npm run backup                       # копия в server/data/backups, хранятся последние 14
node server/backup.js /путь/к/папке  # своя папка; BACKUP_KEEP — сколько копий хранить
```

Копия делается без остановки сервера и проверяется на целостность. Для ежедневной копии в 05:30 — `deploy/hookah-backup.service` и `deploy/hookah-backup.timer`. Копии стоит регулярно уносить с сервера (например, в облачное хранилище).

### Ошибки на страницах

Если у пользователя на странице случается ошибка, сайт сообщает о ней серверу (`POST /api/client-errors`, не больше 5 за визит и 20 в час с адреса) — она попадает в журнал сервера с пометкой «Ошибка на странице».

## Приложение для iPhone

**Без App Store, прямо сейчас.** Откройте сайт в Safari → «Поделиться» → «На экран „Домой“». Сайт откроется на весь экран со своей иконкой. Этой ссылкой можно делиться: https://marlendiusheew-sudo.github.io/hookah-party/

**Нативное приложение** — папка `ios/` (SwiftUI + WKWebView). Сайт встроен в приложение и работает без интернета в демо-режиме; если в `ios/HookahParty/Info.plist` указать `HPServerURL` (адрес сервера на https), приложение работает с настоящими данными. Ссылки на карты открываются в приложениях, календарь — через «Поделиться», обновление — потянуть экран вниз.

```
ios/build.sh sim              # собрать и открыть в симуляторе (подпись не нужна)
ios/build.sh ipa ВАШ_TEAM_ID  # подписанный .ipa для TestFlight / App Store
```

- **На свой iPhone:** откройте `ios/HookahParty.xcodeproj` в Xcode → Settings → Accounts → войдите с Apple ID → у цели HookahParty выберите Team → подключите iPhone → Run. С бесплатным Apple ID приложение работает 7 дней, потом нужно поставить заново.
- **Раздать другим:** нужна программа Apple Developer (99 $ в год). Затем `ios/build.sh ipa TEAM_ID` и загрузка в App Store Connect → TestFlight: друзья ставят приложение по ссылке-приглашению.
- **Неподписанный .ipa** собирается так же, как для iPhone, но с `CODE_SIGNING_ALLOWED=NO`; поставить его можно только после подписи своим Apple ID (например, через Sideloadly).

## Файлы

- `index.html` — разметка, шапка и подвал
- `styles.css` — стили, светлая и тёмная тема
- `app.js` — данные, вход, сборы, каталог, карта, переводы `L('рус', 'eng')`
- `server/` — сервер: `index.js` (HTTP, заголовки, сессии, CSRF), `lib/api.js` (все действия и проверка прав), `lib/db.js` (схема SQLite), `lib/secure.js` (Argon2id, шифрование AES-256-GCM, токены), `lib/guard.js` (лимиты и журнал), `lib/sms.js` (провайдеры SMS)
- `ios/` — приложение для iPhone (проект Xcode, иконка, экран запуска, `build.sh`)
- `manifest.webmanifest`, `icon-*.png` — установка сайта на экран «Домой»
- `art.js` — иллюстрации вкусов табака (SVG, рисуются кодом; набор предметов — поле `art` у табака)
- `map-data.js` — подложка карты и заведения (© участники OpenStreetMap, ODbL)

## Тесты

```
npm install
npm test
```

Проверяются сайт в демо-режиме (около 90 проверок в jsdom) и сервер (вход, права, CSRF, лимиты, регистрация, приглашение по ссылке, заголовки).

Сквозной тест в настоящем браузере — организатор отправляет ссылку, друг входит и отвечает, плюс офлайн-режим:

```
npx playwright install chromium   # один раз
npm run test:e2e
```

На GitHub тесты (включая браузерный), CodeQL и `npm audit` запускаются автоматически при каждой отправке.

Версию файлов `?v=N` в `index.html` повышать вместе с `VERSION` в `sw.js` (офлайн-кеш) — `npm test` это проверяет.
